- Scanner: picture matching + close-up check on the phone, "Is this it?" preview with Not it / Yes, add. Design in `SCANNER_ARCHITECTURE.md`. Real iPhone frames land in `scan-log/` while the dev server runs; check them before tuning.
- Collection page (Oct 6): search, Sort & filter sheet (`utils/collectionQuery.ts`), long-press quick actions (`ItemActionsSheet`), Recently added, Quick stats, CSV export, "Just pulled" panel after a pack. Per-item change for 24h/7d/30d/since added/vs paid (`utils/collectionChange.ts`) in rows, grid and 3D. The Customize sheet saves `settings.collectionLayout` (section order and visibility, grid columns, names, change basis). Graded items only compare against price paid.
- Add celebration: `CelebrateProvider` overlay + `useCelebrate().celebrate({ image, amount, from })`. The card flies to the Collection tab, which bounces with "+N". It's used by the scan preview and sheet and the card and sealed pages. Pass the image URL the screen is already showing so it's cached. The Pull save plays `PackCollectOverlay`, then `showFresh` feeds the collection's Just pulled panel.
- Graded prices: the dev server caches PokemonPriceTracker answers in `.cache/pokeprice` for 3 days and stops calling after a daily-limit 429 until the reset. The app caches for 3 days too, and the card page says when graded prices are paused (free plan = 100 lookups/day).
- Product art: official transparent renders from github.com/1niceroli/ptcg-assets (booster boxes, ETBs, bundles, packs, mini tins, collections) via `src/services/productAssets.ts`. The nightly `card-index` workflow publishes `assets.json` (set → files, from the repo tree + README tables) to the `card-index` branch. `ProductImage` uses render → dev-server cutout → TCGplayer photo.
- Scanner gaps (Oct 6): cards TCGdex has no picture for get fingerprints from fallback images, so the index is about 29.8k cards. English comes from the pokemontcg-data JSON on GitHub, Japanese from TCGCSV product photos. Those URLs go in `meta.json` `images`, and the close-up check uses them too. Code is in `scripts/card-index/fallbacks.mjs`.
- Backup & import (Oct 6): `src/app/backup.tsx`, reached from Customize. Saves a JSON backup (`services/backup.ts`) through the share sheet, restores by adding to or replacing the collection, and imports Collectr/TCGplayer/PullCheck CSVs (`utils/csvImport.ts` → `services/importMatch.ts`, TCGdex set+number+name). Nothing is added before the review step.
- Centering + "Should I grade it?" (Oct 6): `src/app/centering.tsx` (full-screen modal). Opened from the card page button or Should I grade it? in the long-press sheet. It takes a 1600 px photo and runs `PullVision.measureCentering` in a light WebView page (`MEASURE_PAGE_HTML`, no tesseract and no index). Results are L/R and T/B splits on the flattened card plus a PSA cap from `utils/centering.ts`: 10 is safe at 55/45 and gray up to 60/40, 9 is 60–65, 8 is 65–70 and 7 is 70–75. `GradeCalculator` compares raw against PSA 10/9/8 minus `settings.gradingCost`, default $30 per card. It needs a contrasting surface, and full-art cards with no border can't be measured. How it works: `SCANNER_ARCHITECTURE.md` → Centering.
- Foils (Oct 6): `src/three/cardFinish.ts` maps rarity to a finish: plain, window, full, textured, gold, rainbow, illustration, special (SIR), chrome (Futuristic Rare), shiny, pikachu (30th Celebration), reverse or cosmos. The set's era picks the holo pattern: starlight, cosmos, tinsel, sheen, waterweb, line or mirage. `foilMaterial.ts` holds a `LOOKS` table per finish (area, pattern, etch, glitter, tint, metal). Test rig: headless Edge renders the real material on card images at several tilts (scratch `foilrig/`, `node rig.mjs spec.json out.png`). The 30th Pikachu has a swirl on the background, dots on the art and a dotted silver border. Everything in 30th Celebration is foil.
- Default theme = Frutiger Aero (`aero`, shown as "Default"): `AeroSky` background, `Gloss` highlight on accent buttons, `theme.gloss`. `DESIGN_VERSION` 3 switched existing installs once. Graphite is still in Appearance, and built-in theme choices now persist.
- Card swiping: list screens call `setBrowseList` (`services/cardBrowse.ts`) before opening a card. The card page wraps `CardPage` (keyed by id) and swaps cards with `router.setParams({ id, entry, from })`. `CardSwipe` handles the gesture and the "3 of N" pager. `card/[id]` has `fullScreenGestureEnabled: false` so a right swipe doesn't pop.
- Hold to rearrange: `SectionHold` (650 ms hold on any Collection section) turns on arrange mode. `SectionDragList` holds a tile and drags it, with fixed 60 px slots and per-tile Animated positions. The Customize sheet uses it too.
- Tabs (Oct 6): Collection · Scan · Search, and the app opens on Collection. Collection is now `(tabs)/index.tsx` and Scan is `(tabs)/scan.tsx`. `/` means Collection, and the Pull "end without saving" button goes to `/scan`.
- Sets wiggle (Oct 6): hold a set on the Sets screen for 450 ms and every set wiggles. Drag the held set to a new spot and it saves when you let go. While wiggling, a 180 ms hold lifts another set, tapping does nothing, and Done exits. The order is saved for each section in `settings.setOrder` (`yours` or `series:<name>`) and Reset order clears it. Code: `hooks/useSetArrange.ts` and `components/SetArrangeRow.tsx` (a `SetCell` CellRenderer keeps the lifted row on top). This is turned off while searching, and Japanese sets aren't covered.
- Welcome tour (Oct 6): `components/WelcomeTour.tsx` is a 6-page overlay in `AppNavigator`. It shows until `settings.tourDone` is true (Skip or Get started), so existing installs see it once too. Appearance → Help → Replay the welcome tour turns it back on.
